# PRD — 시연용 차시 웹앱 「데이터를 풀어라!」 (성취기준 기반 재구성 데모)

버전 1.0 / 2026-08-05 / 이승엽(장평중, 정보) / 구현: Claude Code
스택: Next.js + **Firebase(Firestore + Storage)** + **Gemini API**(Vercel 서버 라우트) + Vercel 배포 + GitHub — **AICE 캠프 플랫폼과 동일 패턴** (5자리 학번+이름 입장, localStorage 복구, 교사 대시보드 PIN 진입 + onSnapshot 실시간 그리드). 디자인은 본 PRD대로 1차 구현하되 테마 토큰을 분리(추후 design.md로 개편 예정)

## 1. 목적

부스 사례 파트(5분)에서 "성취기준으로 활동을 뽑아 재조합하면 이런 차시 수업 도구가 나온다"를 **실물로** 보여주는 데모이자, 실제 장평중 정보 수업에서 쓸 수 있는 45분 차시 웹앱.

부스 시연 시나리오: 수강생(교사 15명)이 학생 역할로 접속해 활동 클릭·형성평가 제출 → 강사 빔의 교사 대시보드에 완료 상태가 실시간으로 차오르는 장면이 하이라이트. "이것도 바이브 코딩으로 만들었고, 여러분도 만들 수 있습니다"로 마무리.

## 2. 수업 설계 전제 (콘텐츠 재구성 명세)

- 대상: 중학교 정보, 데이터 단원 1차시(45분)
- 성취기준: **[9정02-03]** 실생활의 데이터를 표, 다이어그램 등 다양한 형태로 구조화한다 / **[9정02-04]** 사례를 중심으로 데이터 간의 관계를 파악하고, 데이터에 기반하여 의미를 해석한다
- 재료: School AI 「S.O.S 세계수를 구하라」 2차시 '데이터를 풀어라!'에서 활동 4개만 발췌(공식 연계: 9정02-02~05). 딥링크는 `sai-content-links.json`의 sos > lesson 2 참조:

| 단계 | 활동(차시-활동) | 딥링크 | 유형 |
|---|---|---|---|
| 도입 | 2-1 데이터 수집과 관리(영상 3분43초) | 02/02_01.html?lock=false | video |
| 전개1 | 2-2 나무 데이터 모으기(스프레드시트 기록) | 02/02_02.html?lock=false | interactive |
| 전개2 | 2-7 식물 생장 데이터 시각화하기(차트 선택) | 02/02_07.html?lock=false | interactive |
| 전개3 | 2-8 식물 생장 데이터 해석하기(의견 작성) | 02/02_08.html?lock=false | interactive |

- 산출물: 전개3에서 작성한 "데이터 해석 의견"을 웹앱에 텍스트로 제출
- 형성평가: 자체 3문항(원본 2-9·2-10 퀴즈 내용을 변형)

  2. 선그래프가 적합한 경우는? (객관식: ①시간에 따른 변화 ②항목 비율 ③분포 비교 ④관계 파악 / 정답 ①)
  3. "불량식품 섭취량이 많을수록 수면시간이 길다"는 그래프 해석에서 추가로 확인해야 할 것은? (단답 — 인과·상관 구분 유도)

## 3. 사용자·화면 구조

### 학생 흐름 (`/`)
1. **입장**: 5자리 학번 + 이름 입력(명단 대조 없음 — 부스에서는 임의 입력 허용, `학번 없으면 0000+좌석번호` 안내 문구). localStorage로 재접속 복구
2. **차시 홈**: 상단에 차시명·성취기준 2개(코드+전문 접기)·오늘의 목표 → 단계 카드 5개(도입 영상 / 전개1~3 / 형성평가)
3. **단계 카드**: [활동 열기](새 탭 딥링크) + [완료 체크]. 전개3 카드에는 산출물 텍스트 제출란(수정 재제출 허용). 형성평가 카드는 인앱 3문항 폼(제출 시 객관식 자동 채점, 단답은 저장만)
4. **내 진행 바**: 5단계 완료율. 전체 완료 시 축하 화면
5. **동료 현황판**: 이름·현재 단계만 공개(제출 내용 비공개)

### 교사 대시보드 (`/teacher`, PIN 4자리)
- onSnapshot 실시간: 참여자 × 5단계 완료 그리드(부스 15명 기준 한 화면)
- 형성평가 응답 뷰: 객관식 정답률 도넛 + 단답 응답 리스트(이름과 함께)
- 산출물(해석 의견) 리스트 — 시연 중 몇 개를 빔으로 읽어주는 용도
- 이름 마스킹 토글(빔 표시용), 세션 리셋 버튼(12시 회차 → 15시 회차 사이 데이터 초기화)
- "이렇게 만들었어요" 링크: 제작 프롬프트 요약 페이지(`/how`) — 성취기준 → 활동 발췌 → 바이브 코딩 과정 3단계 소개(부스 멘트용 정적 페이지)

## 4. 데이터 모델 (Firestore)

```
sessions/{sessionId}/students/{studentId}
  { name, studentNo, joinedAt }
sessions/{sessionId}/progress/{studentId}
  { steps: {intro:bool, act1:bool, act2:bool, act3:bool, quiz:bool},
    artifact: string, quiz: {q1:string, q2:number, q3:string, score:number},
    updatedAt }
config/app { teacherPin, activeSession }
```
- sessionId: `booth-1200`, `booth-1500`, `class-...`(학교 사용 대비)
- 보안 규칙: students/progress는 본인 문서만 쓰기, 읽기는 이름·단계 필드만 공개 뷰로. PIN 검증은 클라이언트 최소화(데모 수준 OK, 개인정보는 이름·학번만이므로 세션 리셋으로 파기)

| F3 | 산출물 텍스트 제출·수정, 형성평가 3문항(객관식 자동 채점) |

| F5 | PIN 진입 교사 대시보드: 그리드·정답률·응답 리스트·마스킹·세션 리셋 |
| F5-1 | **Gemini 자동 피드백**: 산출물(데이터 해석 의견)과 형성평가 단답(1·3번) 제출 시 Vercel 라우트 `/api/feedback`이 Gemini로 ①성취기준(9정02-03·04) 관점 한 줄 피드백 ②상/중/하 도달도 제안을 생성 → 학생 화면에 피드백 표시, 대시보드에 도달도 뱃지 표시(교사가 수정 가능한 '제안'으로 취급, 자동 확정 금지) |
| F5-2 | Gemini 호출 실패 시 무피드백으로 조용히 폴백(제출 자체는 항상 성공), 프롬프트·응답 스키마는 상수 분리 |
| F6 | 성취기준 표시: 코드 칩 + 전문 접기(sai-standards-map.json의 9정02-03·04 전문 사용) |
| F7 | `/how` 정적 페이지(제작 과정 3단계) |
| F8 | 세션 전환: config.activeSession 변경만으로 booth-1200 → booth-1500 |

## 6. 비기능
- 15명 동시 접속 무리 없이(Firestore 무료 티어 충분), 대시보드 갱신 지연 1초 내
- 노트북 1366px 기준, 빔 모드 필요 없음(대시보드 폰트만 크게)
- 캠프 종료 후 데이터 삭제 절차 README 포함(AICE 캠프 관례 동일)
- GitHub 리포 공개 대비: API 키·PIN은 환경변수, `.env.example` 제공. Gemini 키는 서버 라우트에서만 사용
- Storage는 현 범위에서 미사용(파일 업로드 제외)이나 초기화만 해둠 — 추후 학교 수업에서 산출물 이미지 제출 확장 대비

## 7. 수용 기준
1. 학생 입장 → 4개 활동 딥링크 새 탭 열림 → 완료 체크 → 강사 대시보드 그리드에 1초 내 반영
2. 형성평가 제출 시 객관식 자동 채점·정답률 도넛 갱신, 단답·산출물에 Gemini 피드백이 5초 내 표시(실패 시 제출은 정상 처리)
3. 산출물 제출 내용이 대시보드 리스트에 표시, 마스킹 토글 동작
4. 세션 리셋 후 그리드 초기화, activeSession 전환 동작
5. 새로고침·재접속 시 본인 진행 상태 복구

## 8. 범위 제외
- 명단 대조·인증(부스 데모 수준), 파일 업로드, 다차시 확장(단일 차시 하드코딩 OK — 단, 단계 데이터는 상수 배열로 분리해 추후 교체 용이하게)
